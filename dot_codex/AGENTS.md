# AGENTS.md

## 言語

全ての応答は日本語で行ってください。
Markdown ドキュメント、コードコメント、ユーザー向け文言も、既存ファイルの言語や外部仕様に合わせる必要がない限り日本語で書いてください。

## 基本方針

- 既存のコード、設計、命名、フォーマットに合わせてください。
- 変更は目的に対して最小限にしてください。不要なリファクタリングや整形変更は避けてください。
- ユーザーが明示していない既存変更を勝手に戻さないでください。
- 不明点があっても、合理的に判断できる場合は仮定を明示して進めてください。
- 判断に迷う内容、破壊的な操作、広範囲な仕様変更は実行前に確認してください。

## コミット

- コミットメッセージは原則として日本語で書いてください。
- Conventional Commits など既存リポジトリの規約がある場合は、接頭辞や形式を維持し、要約と本文を日本語にしてください。
- 外部仕様やプロジェクト規約で英語が必須の場合のみ、その規約を優先してください。

## 作業の進め方

- まず関連ファイルと既存パターンを確認してから変更してください。
- ファイル検索には可能な限り `rg` / `rg --files` を使ってください。
- 変更後は、可能な範囲でテスト、lint、型チェック、ビルドなどを実行してください。
- 検証できなかった場合は、その理由を明記してください。
- 環境構築、追加インストール、外部サービスの利用など、当初の作業範囲を超える対応が必要になった場合は、目的、影響、想定所要時間を説明し、実行前に確認してください。
- 作業が想定より長期化した場合は、完了済みの内容、残作業、長期化の原因を整理し、追加作業と検証範囲の必要性を再評価してください。

## コード品質

- 読みやすく、保守しやすい実装を優先してください。
- 抽象化は、実際に複雑さや重複を減らす場合だけ追加してください。
- コメントは、コードだけでは意図が伝わりにくい箇所に限定してください。
- エラー処理、境界条件、既存の公開 API への影響を確認してください。

## 報告

- 最終回答では、変更内容、確認したこと、未確認のリスクを簡潔にまとめてください。
- ファイルを参照する場合は絶対パスで示してください。
- 長い説明よりも、次に判断・確認すべき点が分かる報告を優先してください。

## ツール利用

- `computer-use` を使う前に、必ずユーザーへ確認してください。
- ユーザーから明示的な許可が出るまでは、`computer-use` 関連ツールを呼び出さないでください。

## GitHub CLI認証

- macOS Keychainを使用する環境で、サンドボックス内の`gh auth status`が失敗した場合は、ホスト環境で同コマンドを読み取り専用で再実行し、その結果を認証状態の判定に用いてください。
- ホスト環境で成功した場合は既存認証で作業を続行し、ホスト環境でも失敗した場合は再認証を案内してください。

## Worktree の利用

- 既定は通常の checkout で作業する。通常の checkout でのブランチ切り替えや作業開始には確認を行わない。
- 追加 worktree を作成・選択・利用する前に、対象パスと理由を示してユーザーへ確認する。ツールが自動で作成・選択した worktree や、別タスク・サブエージェントへの依頼時に worktree を選ぶ場合も同様とする。
- 確認が取れるまでは、状態を把握するための読み取り専用コマンドだけを実行する。
- 手動作成を明示されない限り、`git worktree add` などで worktree を手動作成しない。
